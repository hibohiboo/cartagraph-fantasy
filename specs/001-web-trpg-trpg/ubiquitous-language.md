# ユビキタス言語 (Ubiquitous Language): 非同期TRPG風ゲーム「遺跡漁りとドブさらい」

**Date**: 2025-10-06
**Phase**: Domain-Driven Design Analysis
**Status**: Complete

## 概要
プロジェクト全体で使用される共通言語を定義し、同じ言葉が異なる文脈で異なる意味を持つ場合は、境界づけられたコンテキスト (Bounded Context) で明確に区別する。

---

## 境界づけられたコンテキスト (Bounded Context) の概要

│                                                               │
│  ┌─────────────────┐      ┌────────────────────┐            │

## コンテキスト別ユビキタス言語

### 1. ゲームプレイコンテキスト (Game Play Context)

**責務**: 実際のゲーム進行管理、リアルタイムの状態変更

#### 用語定義

| 用語 | 定義 | 関連エンティティ |
|------|------|------------------|
| **セッション (Session)** | 実際のゲームプレイインスタンス。GMとプレイヤーが特定のシナリオで進行中のゲーム。 | `GameSession` |
| **シーン (Scene)** | ゲーム進行中の現在の状況・場所。プレイヤーがアクションを実行する舞台。 | `SceneState` |
| **イベント (Event)** | ゲーム中に発生する出来事。カード使用・ダイス判定・シーン遷移など。 | `SessionEvent` |
| **プレイヤー (Player)** | セッション参加者。GMを除くゲーム進行の主体。 | `SessionPlayer` |
| **GM (Game Master)** | セッション管理者。シナリオ進行を制御し、イベントを任意発火できる。 | `gm_user_id` |
| **判定 (Check/Roll)** | 行動の成否を決定するダイス振り。2d6基本、修正値・有利/不利を適用。 | `DiceRoll` |
| **ログ (Log)** | プレイヤーアクション・ロールプレイの記録。非同期プレイの進捗把握に使用。 | `EventLog` |
| **アクション (Action)** | プレイヤーがカードを使用・判定を実行する行為。 | `CardUsed`, `DiceRolled` |
| **状態 (State)** | セッションの現在の状況 (募集中、進行中、完了)。 | `SessionState` |
| **巻き戻し/再生 (Rewind/Replay)** | Event Sourcingによる過去のゲーム状態への復元・再実行。 | `EventStore` |

#### 特有の概念

**セッション専用キャラクター (Session Character)**:
- プレイヤーが持つ永続キャラクターのコピー
- セッション中のカード・タグ変更は元のキャラクターに影響しない
- セッション終了時にフィードバックを反映

**パーティ判定 (Party Check)**:
- 複数プレイヤーでの協調判定
- 「全員成功」または「誰か1人成功」の2種類

**可視性 (Visibility)**:
- ログエントリーの閲覧権限 (全員/GM/個人/パーティ)

---

### 2. シナリオ設計コンテキスト (Scenario Design Context)

**責務**: 再利用可能なシナリオ構造の定義、テンプレート管理

#### 用語定義

| 用語 | 定義 | 関連エンティティ |
|------|------|------------------|
| **シナリオ (Scenario)** | 再利用可能な物語構造のテンプレート。複数セッションで使用可能。 | `ScenarioTemplate` |
| **シーン (Scene)** | シナリオ構造の構成要素。目的・イベント・遷移条件を持つ。 | `SceneDefinition` |
| **イベント (Event)** | シーン内で発生する構造化された出来事の定義。トリガー・条件・効果を持つ。 | `EventDefinition` |
| **トリガー (Trigger)** | イベントを発火させる条件 (セッション開始、カード使用、別イベント呼び出し、GM任意発火)。 | `EventTrigger` |
| **条件 (Condition)** | イベント発火の前提条件。タグ所持・カード所持・判定成功など。 | `CompletionCondition` |
| **効果 (Effect)** | イベント発生時の結果。カード配布・タグ付与・シーン遷移など。 | `EventEffect` |
| **遷移 (Transition)** | シーン間の移動。シーン遷移カード使用またはGM操作で発生。 | `SceneTransition` |
| **派生シナリオ (Derived Scenario)** | 既存シナリオを元に作成した新しいシナリオ。オリジナルへの参照を保持。 | `derived_from` |
| **難易度 (Difficulty)** | シナリオの推奨難易度 (初心者、中級者、上級者、エキスパート)。 | `Difficulty` |
| **推奨人数 (Recommended Players)** | シナリオの推奨プレイヤー数範囲。 | `PlayerRange` |

#### 特有の概念

**イベントタイプ (Event Type)**:
- `Narrative`: 物語進行イベント
- `Action`: 行動判定イベント
- `Possession`: 所持判定イベント
- `SceneTransition`: シーン移動イベント
- `CardDistribution`: カード配布イベント

**グラフ構造 (Graph Structure)**:
- シーン・イベントはノード、遷移はエッジとして表現
- React Flowビジュアルエディターで編集

---

### 3. キャラクターコンテキスト (Character Context)

**責務**: プレイヤー資産の長期管理、セッション間の永続化

#### 用語定義

| 用語 | 定義 | 関連エンティティ |
|------|------|------------------|
| **キャラクター (Character)** | プレイヤーが作成・所有する永続的な分身。複数セッションで使用可能。 | `Character` |
| **カード (Card)** | ゲーム進行の核となる要素。アクション・選択肢・所持品・シーン遷移の4種類。 | `Card` |
| **タグ (Tag)** | キャラクター・カードの属性。スキル・状態・実績・条件の4種類。 | `Tag` |
| **持ち込みカード (Personal Card)** | キャラクターが元々所持するカード。セッション開始時に持ち込める。 | `personal_cards` |
| **配布カード (Distributed Card)** | セッション中に獲得したカード。セッション専用キャラクターに追加。 | `session_cards` |
| **履歴 (History)** | キャラクターの過去のセッション参加記録。 | `session_history` |
| **制限 (Restriction)** | 特定シナリオへの参加制限。既にクリア済み・タグ不適合など。 | `scenario_restrictions` |
| **成長 (Growth)** | セッション終了時のフィードバックによるカード・タグ獲得。 | `SessionRecord` |

#### 特有の概念

**カードタイプ (Card Type)**:
- `Action`: アクション用カード (攻撃、防御、探索など)
- `Choice`: 選択肢カード (他の選択肢と排他)
- `Possession`: 所持カード (条件判定用)
- `SceneTransition`: シーン移動カード

**タグカテゴリー (Tag Category)**:
- `Skill`: スキル系 (戦闘、探索、交渉など)
- `Status`: 状態系 (負傷、疲労、強化など)
- `Achievement`: 実績系 (シナリオクリア、特殊行動達成)
- `Condition`: 状況系 (所持判定・イベント条件)

**タグ値 (Tag Value)**:
- `Numeric`: 数値 (レベル、スコアなど)
- `Boolean`: 真偽値 (所持/非所持)
- `Text`: テキスト (説明、フレーバーテキスト)

---

### 4. ユーザーコンテキスト (User Context)

**責務**: プラットフォームアクセス管理、認証・認可

#### 用語定義

| 用語 | 定義 | 関連エンティティ |
|------|------|------------------|
| **ユーザー (User)** | プラットフォーム利用者。シナリオ作成者・GM・プレイヤーのいずれかの役割を持つ。 | `User` |
| **シナリオ作成者 (Scenario Author)** | シナリオを作成・公開するユーザー。 | `author_id` |
| **権限 (Permission)** | ユーザーがアクセスできる機能。作成・編集・削除など。 | `Authorization` (将来) |
| **認証 (Authentication)** | ユーザー本人確認。初期実装では簡素化 (ログイン不要)。 | `Authentication` (将来) |

## 多義語の整理 (Context Map)

### 「イベント (Event)」の多義性

| コンテキスト | 意味 | 型 | 例 |
|--------------|------|----|----|
| **ゲームプレイ** | ゲーム中に発生した実際の出来事 (Event Sourcing) | `SessionEvent` | `CardUsed`, `DiceRolled`, `SceneAdvanced` |
| **シナリオ設計** | シナリオ構造の一部として定義された出来事の設計図 | `EventDefinition` | トリガー・条件・効果を持つイベント設計 |

**関係性**:
- `EventDefinition` (設計図) → `SessionEvent` (実際の発生) への具現化
- シナリオ設計で定義されたイベントが、ゲームプレイで実際に発生

---

### 「シーン (Scene)」の多義性

| コンテキスト | 意味 | 型 | 例 |
|--------------|------|----|----|
| **ゲームプレイ** | セッションの現在の状況・場所 | `SceneState` | 現在シーン、参加プレイヤー、完了進捗 |
| **シナリオ設計** | シナリオ構造の一部として定義されたシーンの設計図 | `SceneDefinition` | 目的、完了条件、イベント一覧、遷移先 |

**関係性**:
- `SceneDefinition` (設計図) → `SceneState` (実行時の状態) への具現化
- シナリオテンプレートのシーン定義が、セッション開始時にシーン状態としてインスタンス化

---

### 「カード (Card)」の多義性

| コンテキスト | 意味 | 型 | 例 |
|--------------|------|----|----|
| **キャラクター** | キャラクターが所有する永続的な資産 | `Card` (personal_cards) | 持ち込みカード、過去のセッションで獲得したカード |
| **ゲームプレイ** | セッション中に使用可能なカード (持ち込み + 配布) | `Card` (session_cards) | セッション専用キャラクターのカード一覧 |
| **シナリオ設計** | シナリオで配布されるカードのテンプレート | `CardTemplate` | シナリオ作成者が定義した配布カード |

**関係性**:
- キャラクターの持ち込みカード → セッション開始時にコピー
- シナリオのカードテンプレート → イベント発生時に配布
- セッション終了時にフィードバックとして永続キャラクターに反映

---

### 「セッション (Session)」の単一性

| コンテキスト | 意味 | 型 | 注記 |
|--------------|------|----|----|
| **ゲームプレイ** | 実際のゲームプレイインスタンス | `GameSession` | **全コンテキストで同一の意味** |

**特記事項**:
- セッションはゲームプレイコンテキストの中核概念
- 他コンテキストからも参照されるが、意味は一貫

## コンテキスト間の翻訳マップ (Context Translation Map)

### シナリオ設計 → ゲームプレイ

| シナリオ設計用語 | ゲームプレイ用語 | 変換処理 |
|-----------------|-----------------|----------|
| `ScenarioTemplate` | `ScenarioInstance` | セッション作成時にインスタンス化 |
| `SceneDefinition` | `SceneState` | 初期シーン設定、現在シーン更新 |
| `EventDefinition` | `SessionEvent` | トリガー発火時にイベント生成 |
| `CardTemplate` | `Card` | 配布イベント発生時にカード生成 |

### キャラクター → ゲームプレイ

| キャラクター用語 | ゲームプレイ用語 | 変換処理 |
|-----------------|-----------------|----------|
| `Character` | `SessionCharacter` | セッション参加時にコピー作成 |
| `personal_cards` | `session_cards` (初期値) | 持ち込みカードをコピー |
| `acquired_tags` | `session_tags` (初期値) | 獲得タグをコピー |

### ゲームプレイ → キャラクター

| ゲームプレイ用語 | キャラクター用語 | 変換処理 |
|-----------------|-----------------|----------|
| `SessionCharacter.session_cards` | `Character.personal_cards` | セッション終了時にフィードバック反映 |
| `SessionCharacter.session_tags` | `Character.acquired_tags` | セッション終了時にフィードバック反映 |
| `SessionRecord` | `session_history` | セッション終了時に履歴追加 |

## 共通語彙 (Cross-Context Terms)

これらの用語は**全てのコンテキストで同じ意味**を持つ。

| 用語 | 定義 | 型 |
|------|------|----|
| **ユーザーID (User ID)** | プラットフォーム利用者の一意識別子 | `UserId` |
| **タイムスタンプ (Timestamp)** | イベント発生・エンティティ作成の日時 | `DateTime<Utc>` |
| **バージョン (Version)** | Event Sourcingでの集約バージョン番号 | `u64` |
| **識別子 (ID)** | エンティティの一意識別子 (UUID) | `SessionId`, `ScenarioId`, `CharacterId`, `CardId`, `TagId` |

## アンチパターン (避けるべき用語)

プロジェクトで**使用してはいけない**曖昧な用語。

| 避けるべき用語 | 理由 | 代わりに使用する用語 |
|---------------|------|---------------------|
| **ゲーム (Game)** | 「セッション」と「シナリオ」の区別が曖昧 | `GameSession` (実行中), `ScenarioTemplate` (テンプレート) |
| **ステータス (Status)** | 「セッション状態」「プレイヤー状態」「キャラクター状態」で意味が異なる | `SessionState`, `PlayerStatus`, `CharacterStatus` |
| **アイテム (Item)** | 「カード」と混同しやすい | `Card` (明示的) |
| **スキル (Skill)** | 「タグ」の一種であることを明示すべき | `Tag (Skill)` または `SkillTag` |
| **ルーム (Room)** | TRPGの「シーン」と混同しやすい | `Scene` (シナリオ構造), `Session` (ゲームインスタンス) |

## ユビキタス言語の進化

### 言語の追加・変更プロセス

1. **新しい概念の発見**: 開発中に新しいドメイン概念が明らかになる
2. **用語の提案**: チーム内で議論し、既存用語との整合性を確認
3. **ドキュメント更新**: `ubiquitous-language.md` に追加
4. **コード反映**: Rust/TypeScript型定義に反映
5. **コミュニケーション**: チーム全体で新用語を共有

### 多義語の解決プロセス

1. **多義性の検出**: レビュー・議論で同じ用語が異なる意味で使われていることを発見
2. **コンテキスト分離**: 異なる意味ごとにBounded Contextを明確化
3. **翻訳マップ作成**: コンテキスト間の変換ルールを定義
4. **リファクタリング**: 必要に応じてコードベースで用語を分離

## まとめ

### 主要な境界づけられたコンテキスト

1. **ゲームプレイコンテキスト**: セッション実行、リアルタイム状態管理
2. **シナリオ設計コンテキスト**: 再利用可能なテンプレート定義
3. **キャラクターコンテキスト**: 長期的なプレイヤー資産管理
4. **ユーザーコンテキスト**: 認証・認可 (将来)

### 多義語の整理

- **イベント (Event)**: 設計図 (`EventDefinition`) vs 実際の発生 (`SessionEvent`)
- **シーン (Scene)**: 設計図 (`SceneDefinition`) vs 実行時状態 (`SceneState`)
- **カード (Card)**: 永続資産 vs セッション一時 vs テンプレート

### コミュニケーション原則

- **明確性**: 曖昧な用語は避け、コンテキストを明示
- **一貫性**: 同じコンテキスト内では常に同じ用語を使用
- **翻訳の明示**: コンテキスト間で用語が変換される場合、明示的に記述

このユビキタス言語により、チーム内のコミュニケーションの齟齬を減らし、ドメインモデルとコードの一貫性を保つ。
